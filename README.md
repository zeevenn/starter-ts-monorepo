# TypeScript Monorepo Starter

A lightweight starter for TypeScript libraries and applications. It uses pnpm workspaces, strict TypeScript, tsdown, Vitest, Changesets, and GitHub Actions without requiring a separate monorepo task runner.

## Features

- `packages/*` for reusable libraries and runtime adapters
- `apps/*` for applications
- Shared TypeScript defaults with project-level `tsconfig.json` files
- Topological package builds and parallel development watchers
- Independent test configuration for every package or app
- Changesets-based versioning and publishing
- CI for lint, typecheck, build, test, and gated releases
- Interactive package generator with scoped-package support

## Requirements

- Node.js LTS
- pnpm 10.18.3 through Corepack

## Getting Started

```bash
corepack enable
pnpm install
```

Create a package:

```bash
pnpm create:pkg @scope/my-package
```

Scoped names use an unscoped workspace directory. For example, `@scope/my-package` is created under `packages/my-package`.

The generator asks for a description and whether the package is private. Public packages require a GitHub `origin` remote. If Git author information is unavailable, the generator asks for it before writing files.

## Workspace Layout

```text
apps/
  my-app/
packages/
  my-package/
scripts/
tsconfig.base.json
```

Each project owns its build, typecheck, and test configuration. Library packages generated by `create:pkg` include tsdown, TypeScript, and Vitest configuration by default. Applications can use framework-specific commands such as `vue-tsc`, Playwright, or Vitest Browser Mode.

## Commands

```bash
pnpm build       # Build workspace projects in dependency order
pnpm dev         # Start all project watchers in parallel
pnpm lint        # Lint the repository
pnpm typecheck   # Check root scripts and every workspace project
pnpm test        # Test root scripts and every workspace project
pnpm create:pkg  # Create a package interactively
```

## Workspace Dependencies

Declare package relationships in the consuming project's `package.json` through pnpm instead of adding TypeScript path aliases manually:

```bash
pnpm --filter @scope/consumer add @scope/dependency --workspace
```

This produces a workspace dependency such as:

```json
{
  "dependencies": {
    "@scope/dependency": "workspace:*"
  }
}
```

## Testing

Every package or app defines its own `test` command and test configuration. The root command discovers and runs those commands through the workspace, allowing Node, Vue, browser, and integration-test projects to use different environments.

Generated packages start with:

```json
{
  "scripts": {
    "test": "vitest run",
    "test:watch": "vitest"
  }
}
```

## Releases

Add a changeset for user-visible changes to publishable packages:

```bash
pnpm changeset
```

Changesets accumulate in a release PR after reaching `main`. Packages are published only when that release PR is merged, so maintainers control release frequency by deciding when to merge it.

To enable automated npm publishing, configure the repository's GitHub Actions settings:

- Secret: `NPM_TOKEN`
- Variable: `NPM_PUBLISH_ENABLED=true`

See [CHANGESETS.md](./CHANGESETS.md) for the complete workflow.
